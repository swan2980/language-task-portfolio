## 模块四：这次评测做了什么

**一句话结论**：Whisper small 在粤语「逐字朗读」场景下出现输出多样性塌缩，基本不可用。

**数据**
- 例粤语田野调查录音《江曾摄》408 秒
- 《江摄》字表 54 条，其中 41 条成功采集读音；13 条因发音人无法引导而缺失，评测时整行剔除（否则会凭空多出 13 处「漏识」）

**系统**：Whisper small（faster-whisper 1.2.1，int8 量化，language=zh）

**流程**：VAD 分段 → 逐段转写 → 与字表对齐 → 双口径 CER 计算 → 音系错误归因

**三个发现**

1. **输出多样性塌缩** —— 41 条参考字涵盖 20 种不同音节、10 类声母，模型输出的 58 个单元中 43 个是同一个字「膀」，去重后仅 6 种。
2. **同音字归并，字面 CER 系统性虚高** —— 「邦→帮」「庞→旁」「窗→枪」字面全错、音值全对。方言调查按「音」列字，同一个音底下是一组同音字，模型只保留一个字形。
3. **通用粤拼词表不适用于本方言点** —— 字表记「江 / 扛 / 豇」为 `kɔŋ 51`（见母读 k-），标准粤拼却是 `gong1`（g-）。用通用词典作基准会把正确的判成错的。

**方法论产出：双口径 CER**

| 口径 | 计算方式 | 用途 |
|---|---|---|
| 字面 CER | 严格按汉字比对 | 与行业常规指标对齐 |
| 音值 CER | 同音字判为正确，只计真音错 | 反映实际可用性 |

两者之差即「同音字归并造成的假错误比例」。错误再按声母 / 韵母 / 声调 / 增字 / 漏识细分归因。

**局限（如实说明）**
- 逐段对应关系尚未逐条人工复核，结论基于序列整体统计
- 单一方言点、单一发音人，不可外推至粤语整体
- 未做参数对比实验（model size、language=zh / yue）

## 复现方式

评测在 macOS 本地完成（Python 3.13 + venv）：

```bash
python -m venv venv
source venv/bin/activate
pip install faster-whisper av==18.0.0 ToJyutping
```

模型下载需走镜像（国内直连 HuggingFace 会 502）：

```bash
export HF_ENDPOINT=https://hf-mirror.com
export HF_HUB_DISABLE_XET=1
```

流程脚本：`01 环境自检 → 02 音频清单 → 03 Whisper 转写（含 VAD）→ 04 长音频切片 → 05 双口径 CER 计算`
